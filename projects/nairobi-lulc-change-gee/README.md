# Nairobi County LULC Change & Vegetation Condition | Google Earth Engine

**Portfolio project | GIS · Remote Sensing · Land Use/Land Cover · Environmental Monitoring**

This project provides a reproducible Google Earth Engine (GEE) workflow to examine land-cover patterns and vegetation-condition differences in Nairobi County, Kenya.

## Study design

- **Study area:** Nairobi County, Kenya.
- **Baseline window:** 2017–2019.
- **Comparison window:** 2023–2025.
- **Land-cover source:** Google/WRI Dynamic World V1, 10 m.
- **Vegetation source:** Sentinel-2 Level-2A surface reflectance harmonized collection.
- **Platform:** Google Earth Engine JavaScript Code Editor.
- **Primary outputs:** two period land-cover maps, exploratory class-transition layer, class-area tables, median NDVI composites, NDVI difference layer and Drive export tasks.

The windows are deliberately multi-year composites to reduce dependence on a single acquisition date. Dynamic World labels are filtered by a top-class probability threshold of 0.60 before temporal mode compositing. This threshold is a workflow choice and should be tested through sensitivity analysis.

## Questions

1. What are the dominant mapped land-cover classes in the two analysis windows?
2. How do mapped class areas differ between the baseline and comparison windows?
3. Where do the mapped land-cover labels transition between periods?
4. How does median NDVI differ between the two windows?
5. Which locations should be prioritised for independent reference-data checks and field interpretation?

## Data sources and rationale

| Dataset | Earth Engine ID | Use | Key caveat |
|---|---|---|---|
| Dynamic World V1 | `GOOGLE/DYNAMICWORLD/V1` | 10 m model-derived land-cover labels and class probabilities | Predictions require independent validation; confidence threshold affects mapped area |
| Sentinel-2 SR Harmonized | `COPERNICUS/S2_SR_HARMONIZED` | Surface reflectance and NDVI | Cloud/shadow masking and seasonal matching affect composites |
| FAO GAUL 2015 Level 1 | `FAO/GAUL/2015/level1` | Administrative study-area boundary | Confirm boundary name, vintage and suitability for the intended reporting purpose |

Dynamic World has nine land-cover classes and is available from 2015-06-27. Sentinel-2 SR Harmonized is available from 2017-03-28. Refer to the linked official dataset documentation below.

## Run the analysis

1. Sign in to [Google Earth Engine Code Editor](https://code.earthengine.google.com/). An active Earth Engine account/access is required.
2. Open `gee/nairobi_lulc_change_ndvi.js` from this repository and copy the complete script into a new Code Editor script.
3. Click **Run**. Inspect the Console for boundary feature count and image collection counts.
4. Switch map layers on/off to inspect baseline/recent LULC and NDVI layers.
5. Open **Tasks** and start the CSV and GeoTIFF exports to Google Drive.
6. Save the script in your Earth Engine repository and capture genuine screenshots of the Code Editor, map layers, Console and completed export tasks.
7. Download the outputs and add them to `outputs/` only after checking that they exported correctly and are approved for public sharing.

- `Nairobi_LULC_2023_2025.tif`

The CSV area table reports hectares by class for each period. The transition raster encodes baseline and recent class labels as `baseline_class * 10 + recent_class`; interpret the code using the class legend in the script.

## Method and interpretation notes

- Dynamic World is a model-derived product, not a locally trained classification. Its temporal mode composite is not a substitute for an independently validated land-cover classification.
- A difference in class area is a mapped difference between two composite windows. It is not automatically proof of a specific land conversion process.
- NDVI is a vegetation greenness indicator. NDVI change alone does not establish vegetation degradation, restoration, biomass change or ecological condition.
- Seasonal rainfall, phenology, image availability, cloud masking, urban shadows and mixed pixels can influence comparisons.
- Use the same seasonal window in both periods where possible. This initial script uses full calendar-year multi-year windows; consider a dry-season or wet-season matched analysis as a sensitivity check.
- Review the confidence threshold (0.60), boundary source and cloud mask. Record any changes in the final report.
- For a defensible accuracy assessment, create stratified reference samples for each period, interpret independent high-resolution reference imagery or field observations, and report confusion matrices and class-specific/user's/producer's accuracy. Avoid using Dynamic World itself as the independent validation reference for Dynamic World-derived labels.

## Recommended next-stage validation

1. Verify Nairobi County geometry and compare with an authoritative county boundary.
2. Inspect image counts and seasonal coverage for both windows.
3. Generate stratified sample points across mapped classes and change categories.
4. Interpret reference labels independently using suitable high-resolution imagery or field observations.
5. Report sample design, reference dates, confusion matrix and uncertainty.
6. Investigate mapped change hotspots with local context and ancillary data.
7. Only then write quantified findings and conclusions.
